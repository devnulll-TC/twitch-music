## YouTube и yt-dlp

### Без кук YouTube не отдаёт ничего
С датацентрового IP **0 из 6** популярных треков: `Sign in to confirm you're not a bot`.
Прошёл только один старый ролик. Это не настройка — это позиция YouTube к серверным IP.

### PO-token провайдер сам по себе не спасает
Контейнер `tm-pot` (`bgutil-ytdlp-pot-provider`) поднят, токены выдаёт, в отладке видно,
что подхватывается — результат всё равно **0 из 6**. Оставлен как подпорка к кукам, но
считать его решением нельзя.

### Рабочая формула — куки + решатель JS-challenge
```
yt-dlp --cookies secrets/youtube-cookies.txt --remote-components ejs:github …
```
даёт **6 из 6**. Одного установленного `deno` мало: без `--remote-components ejs:github`
падает `Signature solving failed` / `Requested format is not available`.
Оба флага живут в `Resolver.baseArgs()` — не выкидывать «за ненадобностью».

### Куки — с одноразового Google-аккаунта, и это важно
Экспортированы только с `.youtube.com` (24 куки); файл со всеми доменами Google на сервер
сознательно не клали. **Этим аккаунтом нельзя логиниться больше нигде** — ротация сессии
обнулит куки на сервере. Протухают за недели, см. [«Сломается само»](#сломается-само).

### `--print` неявно включает `--simulate`
Файл не скачивается, ошибок нет, всё «успешно». Для «скачать и напечатать путь» обязателен
`--no-simulate` (см. `Resolver.Download`).

### В плоском поиске нет обложки, а у SoundCloud — и длительности
`--flat-playlist` отдаёт `thumbnail=NA` **всегда**, у обоих источников. Обложку YouTube
строим из id (`i.ytimg.com/vi/<id>/mqdefault.jpg`), остальным нужен дозапрос. У SoundCloud
в плоском поиске нет и `duration` — без дозапроса отсев по длине не работает именно там,
где нужнее всего (часовые миксы).

### Длительность приходит дробной
`"250.473"`, а иногда `"NA"`. Целочисленный разбор молча давал ноль → отсев по длине
переставал работать. Только `ParseFloat` (`parseDuration`).

### Прямой эфир качается «до конца стрима»
То есть никогда. Отсекаем по `is_live` до скачивания.

### «Первый результат поиска» — плохой выбор для Spotify-ссылок
По названию наверх лезут часовые расширенные версии, склейки и реакции (ловили на Daft
Punk: первый результат — 10-минутный, отвалился по лимиту длины). Поэтому `ytsearch5` +
ближайший по длительности ±20 сек (`searchBest`).

## liquidsoap

### Пути внутри контейнера ≠ пути на хосте
Сервис видит кэш как `/root/twitch-music/cache`, liquidsoap — как `/cache`. При пуше
хостового пути заявка **принимается и молча выбрасывается**: в эфире тишина, в логах
ни одной ошибки. Лечится трансляцией (`PLAYER_CACHE_DIR` → `App.playerPath`).
**Самая дорогая грабля проекта** — искать нечего, ошибок нет.

### Кастомные метаданные режутся молча
По умолчанию на выход экспортируются только стандартные теги. `source`, `requested_by`,
`web_url` доедут до оверлея, только если перечислены в
`settings.encoder.metadata.export`. У скачанных с YouTube m4a своих тегов почти нет,
поэтому оверлей целиком живёт на `annotate:`.

### `stream.metadata` врёт после конца трека
Продолжает отдавать последний игравший трек. Признак тишины — **`stream.remaining < 0`**.
Без этой проверки панель уверяет, что играет то, что кончилось минуту назад.

### `getenv("X")` не работает в 2.3
Сигнатура — `(?default, name)`, первый безымянный аргумент съедается как default.
Правильно: `environment.get("X")`.

### Старт с середины — через `liq_cue_in`, а не `cue_cut`
В 2.3 разбор заявки понимает `liq_cue_in` прямо в `annotate:`. Используется для паузы.

### Поток обязан быть непрерывным
`blank()` в `fallback` — не косметика: обрыв потока роняет источник в OBS по таймауту.

### Перезапуск контейнера рвёт соединение OBS
И OBS **не всегда переподключается сам**. Перед `docker compose restart` предупреждать
стримера, если идёт эфир.

## Twitch

### Награду обязано создать наше приложение
Менять статус активаций (подтверждать и **возвращать баллы**) Twitch разрешает только
приложению-создателю награды. Награда, сделанная стримером руками в панели, для нас
навсегда read-only — а возврат баллов и есть смысл всей затеи.

### `should_redemptions_skip_request_queue: false` — обязателен
При `true` активация сразу помечается FULFILLED, и вернуть баллы уже нельзя.

### Логины модеров проверять через API, а не со слов
В список доступа к панели сначала попал `hmosha` — **посторонний человек**; нужный ник
`hmosha_`, с подчёркиванием. Поймали проверкой через Helix. Любой ник перед добавлением
в `PANEL_ALLOW` сверять запросом к `/helix/users`.

### `force_verify=true` при OAuth
Иначе, если в браузере залогинен не тот аккаунт, Twitch молча подключит его — и бот
начнёт писать в чат от имени стримера.

### Access-токен живёт 4 часа
Значит, переживает не каждый эфир. Все вызовы — только через `TokenStore.Get`, который
рефрешит. Прямое чтение поля = бот молча замолкает в середине стрима.

### EventSub просит переподключаться сам
`session_reconnect` — штатное поведение, не сбой. Игнорировать нельзя: соединение умрёт.
`revocation` означает, что сменились права или удалена награда.

### IRC рвётся регулярно, и на `PING` надо отвечать
Не ответить — отключение через минуту. Сообщение длиннее 500 символов Twitch обрежет
(режем сами на 450).

### Отдельных «бот-аккаунтов» у Twitch нет
`devnulll_music` — обычный пользовательский аккаунт, выданный модератором канала. Это
норма, Twitch сам так советует. Verified Bot понадобится только на мульти-тенанте.

## Spotify

### Звук Spotify невозможен. Закрыто экспериментом, не переоткрывать
Spotify перевёл лицензионные треки на собственный DRM **PlayPlay**; легаси-механизм
AES-ключей, на котором работают все сторонние клиенты, для них больше не обслуживается:
`failed retrieving aes key with code 1` на каждом треке. Проверено:

- go-librespot v0.8.0 (свежий, с фиксом альтернативных треков);
- аккаунт с **оплаченным Premium** — гипотеза «нет подписки» неверна;
- с американского IP на другом VPS, 55 отказов подряд — гипотеза «регион» тоже неверна.

Единственный «настоящий фикс» — реализация PlayPlay, то есть снятие DRM. Не делаем.
`go-librespot` на сервере установлен и авторизован, но **демон погашен**, источник
`spotify` в `radio.liq` спит с флагом `spotify_on=false`. Оставлен как археология.

### Spotify остаётся как каталог
Web API (client credentials): название, исполнитель, длительность, разбор ссылок.
Покрытие «Spotify → YouTube/SoundCloud» замерено на злой выборке: **58 из 59 (98%)**,
YouTube даёт 94%, SoundCloud добирает остальное. Цепочка из двух источников не для красоты.

### Две грабли Spotify API, каждая стоила перезапуска замера
- `limit > 10` в поиске → `Invalid limit`, хотя в их доках всё ещё «до 50».
- **`popularity` больше не отдаётся в поиске** — ноль даже у мировых хитов. «Непопулярность»
  брать глубиной выдачи (`offset`), а не этим полем.

### Альбомы/плейлисты/исполнители отклоняются осознанно
Одна активация награды за 500 баллов иначе забивает очередь на час.

## Go и сам сервис

### `sync.Mutex` внутри структуры, которую копируешь
Копия мьютекса не защищает оригинал. Поэтому `SettingsData` (данные) отделён от
`Settings` (замок). Поймал `go vet`.

### HTML-шаблон нельзя подставлять через `Fprintf`
В CSS полно `%` → `unknown verb`. Используется простая замена `{{PLACEHOLDER}}`.
Тоже поймал `go vet` — **гонять `go vet` перед каждым деплоем**.

### Проверка сборки через пайп врёт
`go build … && echo OK | head` — `head` съедает код возврата, и «успех» печатается всегда.
Смотреть `$?`.

### Счётчик слушателей врал дважды
1. Подсчёт сокетов **на хосте** — докерный NAT прячет реальные соединения, панель
   показывала «OBS не подключен», когда OBS играл.
2. Счётчик событий в самом liquidsoap (`on_connect`/`on_disconnect`) — обработчик разрыва
   не вызывается при аварийном отвале клиента, а OBS отваливается именно так; счётчик
   уползал вверх и застревал на «подключен».

Работает третий вариант: чтение `/proc/<pid контейнера>/net/tcp`. ⚠️ В `radio.liq` при
этом до сих пор живёт серверная команда `tm.listeners` и метод `Player.Listeners()` —
**они не используются**, панель берёт число из `listeners.go`. Не перепутать при правках.

### `-1` вместо `0`, когда посчитать не удалось
«Не знаю» нельзя показывать как «никого нет» — иначе стример будет чинить работающий поток.

### Пустой срез вместо `nil` в JSON
`nil` уезжает как `null`, и фронтенд падает на `len()`.

## Инфраструктура и сеть

### Docker публикует порт в обход ufw
В ufw для `8000/tcp` есть правило только на `wg0`, но снаружи порт **открыт**, потому что
его опубликовал контейнер. Единственная защита потока — HTTP basic-auth harbor'а (без
пароля 401, с паролем 200; проверено снаружи). Помнить об этом при любом аудите: `ufw status`
здесь не отражает реальность.

### Звук идёт мимо Cloudflare намеренно
Круглосуточный поток через free-туннель — серо по ToS и лишний прокси на 16 тыс. км до
Сиднея. Веб-морда, наоборот, ходит через готовую дверь `get.dev-nulll.com`
(cloudflared → nginx `127.0.0.1:8080`).

### `auth_basic off` для нашего location — обязательно
Twitch дёргает OAuth-callback сам и форму логина показать не может; OBS тоже. Защита пути —
длинный случайный `WEB_PREFIX`. Значит, **префикс = секрет**: в логах, скриншотах и
переписке маскировать.

### Пароль потока зашит прямо в URL для OBS
`http://user:pass@host:8000/mount` — OBS не умеет показывать форму авторизации. Ссылка из
панели равносильна паролю.

### Ссылка на OBS-док — тоже пароль
Ключ постоянный (`HMAC(PANEL_SECRET,"obs-dock-v1")`), кому попало не пересылать. Отзыв —
только сменой `PANEL_SECRET` (заодно разлогинит всех в панели).

### Мьют в OBS соединение не рвёт
Если слушателей 0 — дело **не** в мьюте, а в разорванном соединении.

## Синхронизация и сборка

### Истина по коду — локальная копия
`~/Desktop/twitch-music/` → VPS `rsync`'ом. **На VPS исходники не править.**

### `rsync` затирал серверные `go.mod` / `go.sum`
После `go get` на сервере зависимость прописывалась там, а следующий синк из локальной
копии её сносил — сборка падала «на ровном месте». После установки любого пакета на
сервере **сразу синхронизировать `go.mod`/`go.sum` обратно к себе**.

### Анкорить exclude-паттерны слешем
Правило со стенда вообще: `--exclude 'foo'` матчит любой компонент пути и молча выкидывает
вложенные каталоги с тем же именем. Писать `--exclude '/foo'`.

### Проект не под git
Ни локально, ни на VPS. Единственная защита от «испортил и не помню как было» — эта
документация и `deploy/`-снимки. Завести репозиторий — самая дешёвая страховка из
оставшихся.

## Сломается само

Список того, что сейчас работает, но имеет срок годности или растёт без присмотра.

| Что | Симптом | Что делать |
|---|---|---|
| **Куки YouTube протухают** (недели) | все заказы с YouTube падают с `Sign in to confirm…`; SoundCloud продолжает работать | переэкспортировать куки того же одноразового аккаунта. **Health-check с алертом не сделан** — стоит сделать |
| **`cache/` растёт без ротации** | сейчас ~230 МБ / 57 файлов, диск 36% — до боли далеко, но чистки нет вообще | добавить чистку по возрасту (`find cache -mtime +30 -delete`) |
| **`secrets/tokens.json` нигде не бэкапится** | потеря = ручная переавторизация обеих ролей, стример нужен лично | класть в бэкап (файл маленький, 664 байта) |
| **yt-dlp стареет быстрее всего** (сейчас `2026.07.04`) | YouTube меняет защиту → «форматов нет» | обновлять до, а не во время эфира; после обновления прогонять реальный заказ |
| **Очередь живёт только в памяти** | перезапуск сервиса теряет заказы, за которые зрители уже отдали баллы | помнить при рестартах; при желании — сериализовать очередь на диск |
| **Мониторинга нет** | если `tm-service` или контейнер умрёт ночью, узнаем от стримера в эфире | `Restart=always` в юните есть, но алертов нет; на стенде уже живёт `devnulll-monitor.sh` — можно подцепить `/health` туда |
| **Один канал, один набор токенов** | любая попытка второго канала потребует переделки `TokenStore`, `Chat`, EventSub | не обещать мульти-тенант «за вечер» |
