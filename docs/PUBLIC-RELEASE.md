# Что нужно сделать, чтобы открыть исходники

**Статус:** репозиторий приватный и таким остаётся. Это список условий, при
которых его можно будет сделать публичным — записан 15.08.2026, пока причины
свежи. Ничего из этого не делается «заодно», каждый пункт — отдельная работа.

Коротко: сейчас проект не продукт, а **один экземпляр, приваренный к одному
стримеру**, и часть его защиты держится на том, что адреса никто не знает.

---

## 1. Отвязка от конкретного канала

В коде и конфигах зашит один заказчик:

- `BROADCASTER_LOGIN=f1pah`, `BOT_LOGIN=devnulll_music` — дефолты в коде;
- `PANEL_ALLOW` — список логинов модеров канала;
- `REWARD_TITLE=Заказать трек` — название награды на русском;
- `PUBLIC_BASE=https://get.dev-nulll.com` — дефолт, зашитый в сервис.

Публичной версии нужен нормальный конфиг на экземпляр (или мультиарендность),
где ничего из этого не является значением по умолчанию.

## 2. Секретность как защита должна уйти

Панель, OAuth-возврат и OBS-док живут под **длинным случайным префиксом пути**,
и `auth_basic` для него намеренно отключён — иначе Twitch не отдаст callback, а
OBS не покажет форму логина. Пока адрес знают трое, это работает. В публичном
проекте так нельзя: нужен настоящий вход в панель и подписанные ссылки для OBS
вместо «секретного» URL.

Сюда же: ключ в OBS-доке у стримеров вставлен один раз, и кнопки
«перевыпустить ссылку» до сих пор нет. Она обязана появиться раньше публикации,
иначе засветившийся в эфире ключ нечем отозвать.

## 3. Звук

Поток отдаётся напрямую портом `8000` по **http**, мимо nginx и Cloudflare:
круглосуточный поток через бесплатный туннель — серо по ToS, а лишний прокси на
16 тысяч километров добавлял бы задержку. Защита порта — только пароль harbor,
`ufw` его не прикрывает.

Для публичного продукта это придётся решать честно: TLS на самом потоке или
свой прокси. Тот же вопрос блокирует переезд на `music.devnulll.dev` — страница
на `.dev` будет строго https, а браузер не пустит http-аудио (mixed content).

## 4. Личные учётные записи

`librespot/state.json` — **реальные учётные данные Spotify** (reusable auth
blob). Файл в `.gitignore` и не попал ни в один коммит: проверено при импорте.
Публичная версия не должна вообще требовать чьего-то личного аккаунта — а
поскольку звук из Spotify технически закрыт (DRM PlayPlay), это скорее повод
выкинуть зависимость, чем описать её в README.

Проверить перед публикацией: `nginx-dev-nulll.bak` (боевые префиксы, тоже в
`.gitignore`) и всю историю на предмет `.env`.

## 5. Установка и лендинг

Сейчас разворачивание — это набор ручных шагов: docker compose, три
systemd-юнита, локация в nginx, `.env` с двенадцатью переменными, деплой
`rsync`'ом с локальной машины. Для публики нужен образ или инсталлятор, а к
нему — лендинг на `music.devnulll.dev` с документацией по подключению OBS.

## 6. Формальности

- **Лицензии нет.** Выбрать до открытия, не после.
- Решить, что делать с `tools/` — разовые исследовательские скрипты.
- README сейчас честно описывает стенд одного заказчика: адрес VPS, каталог,
  устройство публичной двери. Для публичного репозитория это переписывается
  целиком.

---

## Порядок, если браться

1. Отвязать от канала (п. 1) — без этого остальное не имеет смысла.
2. Заменить секретность на авторизацию (п. 2) и решить звук (п. 3).
3. Убрать личные учётки (п. 4).
4. Установка + лендинг (п. 5), лицензия (п. 6).
5. Прогнать историю на секреты ещё раз и только тогда переключать видимость.
