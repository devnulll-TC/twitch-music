# Архитектура и кодовая база

## 1. Общая картина

```
   зритель                        Twitch                         наш VPS (Frankfurt)
 ┌──────────┐   баллы канала   ┌───────────┐   EventSub WS   ┌─────────────────────────┐
 │ награда  │ ───────────────► │ Twitch    │ ───────────────►│  tm-service (Go)        │
 │ «Заказать│                  │ Helix API │ ◄───────────────│  :8030 на 127.0.0.1     │
 │  трек»   │ ◄─ возврат баллов└───────────┘   PATCH статуса │                         │
 └──────────┘                        ▲  IRC :6697            │  ┌───────────────────┐  │
                                     └───────────────────────┤  │ resolver (yt-dlp) │  │
                                            чат-ответы       │  └─────────┬─────────┘  │
                                                             │            │ файл в cache/
 ┌──────────┐  HTTPS через cloudflared → nginx :8080         │  ┌─────────▼─────────┐  │
 │ панель   │ ───────────────────────────────────────────────┤  │ queue (наша!)     │  │
 │ и OBS-док│      /<WEB_PREFIX>/panel, /dock, /api/…        │  └─────────┬─────────┘  │
 └──────────┘                                                │            │ telnet 1234│
                                                             │  ┌─────────▼─────────┐  │
 ┌──────────┐   MP3 192k, прямой порт 8000 (мимо CF)         │  │ liquidsoap (docker)│ │
 │ OBS Азима│ ◄───────────────────────────────────────────────┤ │ output.harbor ×2   │ │
 └──────────┘   /<mount> — эфир, /<monitor> — наушники       │  └───────────────────┘  │
                                                             └─────────────────────────┘
```

Два процесса и ничего больше:

| Компонент | Что это | Где |
|---|---|---|
| `tm-service` | весь мозг: Twitch, резолвер, очередь, панель | systemd-юнит на хосте, слушает `127.0.0.1:8030` |
| `tm-liquidsoap` | только звук: очередь заявок → MP3-поток | docker-контейнер, `0.0.0.0:8000` + `127.0.0.1:1234` |
| `tm-pot` | PO-token провайдер для yt-dlp (подпорка к кукам) | docker-контейнер, `127.0.0.1:4416` |

Между сервисом и плеером — **telnet-протокол liquidsoap** на `127.0.0.1:1234`: текстовые
команды, ответ до строки `END`. Всё управление звуком (`requests.push`, `stream.skip`,
`stream.remaining`, `var.set tm_volume`) идёт через него.

## 2. Путь одного заказа

1. Зритель активирует награду → Twitch шлёт `channel.channel_points_custom_reward_redemption.add`
   в наш **EventSub WebSocket** (`twitch_eventsub.go`).
2. `App.Enqueue` (`main.go`):
   - `Resolver.Resolve` — понять, что заказали. Ссылка идёт в yt-dlp как есть; свободный
     текст → `ytsearch1:`; префикс `sc:` → `scsearch1:`; ссылка Spotify → каталог Spotify,
     затем поиск той же записи на YouTube по длительности (`searchBest`, `ytsearch5` ±20 сек).
   - Отсев **до скачивания**: прямой эфир, слишком длинный трек.
   - `Resolver.Download` — yt-dlp кладёт `bestaudio[ext=m4a]` в `cache/<source>-<id>.m4a`.
     Повторный заказ того же трека файл не перекачивает.
3. Трек ложится в **нашу очередь** (`queue.go`), не в очередь плеера.
4. `App.pump()` (тикер 1 сек) отдаёт плееру **ровно один** трек и **только когда в эфире
   тишина** (`stream.remaining < 0`). Метаданные для оверлея едут в `annotate:`.
5. Активация закрывается: `FULFILLED` при успехе, `CANCELED` (= **возврат баллов**) при
   любой неудаче; в чат уходит причина.

## 3. Ключевые инварианты

Их легко нарушить рефакторингом, и каждый стоил отладки в эфире.

1. **Очередь принадлежит нам, а не liquidsoap.** Плеер умеет только «в конец» и
   «пропустить», так что редактировать очередь из панели можно, лишь пока треки лежат у нас.
   В очереди плеера всегда ≤ 1 заявки.
2. **Трек подаётся только в тишину.** Подача впрок (за 5 сек до конца) даёт бесшовный стык,
   но ломает паузу, скип и «сейчас играет». Цена нынешнего решения — стык до секунды.
3. **Поток непрерывен.** `fallback(track_sensitive=false, [requests, blank()])` — при пустой
   очереди в эфир идёт тишина. Обрыв потока = OBS отваливается по таймауту, и стример руками
   переподключает источник посреди эфира.
4. **Награду создаёт наше приложение.** Twitch разрешает менять статус активаций (в т.ч.
   возвращать баллы) только создателю награды. Награда, сделанная руками в панели Twitch,
   для нас нередактируема.
5. **Токены — только через `TokenStore.Get`**, который освежает access-токен. Прямое чтение
   сохранённого поля отвалится через 4 часа эфира.
6. **Путь к файлу транслируется** из хостового (`/root/twitch-music/cache`) в контейнерный
   (`/cache`) — см. `App.playerPath`.

## 4. Карта кодовой базы

Всё в одном пакете `main`, `service/` — 14 файлов, ~2.5k строк. Никакого фреймворка;
единственная внешняя зависимость — `github.com/gorilla/websocket`.

### Ядро

| Файл | Строк | Ответственность | Что смотреть в первую очередь |
|---|---:|---|---|
| `main.go` | 325 | конфиг из `.env`, сборка `App`, маршруты HTTP, `Enqueue` | `Config` (что вообще настраивается), `App` (всё состояние), список роутов |
| `queue.go` | 226 | наша очередь + `pump()` + пауза/возобновление | `pump()` — единственное место, где трек попадает в плеер |
| `player.go` | 204 | telnet-клиент liquidsoap | `cmd()` — протокол; `Remaining() == -1` значит тишина |
| `resolver.go` | 343 | yt-dlp: поиск, метаданные, скачивание | `baseArgs()` — обязательные флаги YouTube; `Download` |
| `settings.go` | 55 | настройки, меняемые в эфире (`settings.json`) | `SettingsData` отделён от мьютекса намеренно |
| `listeners.go` | 95 | сколько клиентов слушают поток | комментарий сверху: две предыдущие реализации врали |

### Twitch

| Файл | Строк | Ответственность |
|---|---:|---|
| `twitch_auth.go` | 342 | OAuth обеих ролей, refresh, хранилище токенов, страница `/twitch/` |
| `twitch_api.go` | 182 | Helix: `EnsureReward`, `FinishRedemption` (возврат баллов), подписка EventSub |
| `twitch_eventsub.go` | 126 | WebSocket активаций награды, `handleRedemption` |
| `twitch_chat.go` | 222 | IRC-чат: команды, права по бейджам, ответы |

Роли и права (`roleScopes`):

- `bot` — `chat:read`, `chat:edit`. Аккаунт `devnulll_music`, мод в канале.
- `broadcaster` — `channel:manage:redemptions`, `channel:read:redemptions`. Аккаунт f1pah.
  **Только он умеет возвращать баллы.**
- `panel` — **пустой scope**: Twitch используется лишь для подтверждения личности, токен
  панели не сохраняется вовсе.

### Веб

| Файл | Строк | Ответственность |
|---|---:|---|
| `panel.go` | 371 | сессии (HMAC-кука 30 дней), список доступа, API панели, `applySettings` |
| `panel_html.go` | 479 | HTML/CSS/JS панели и OBS-дока, оформление токенами лендинга |

Аутентификация панели: вход через Twitch → проверка логина по `PANEL_ALLOW` + логин
стримера → кука `tm_panel` = `base64(login|exp).base64(HMAC-SHA256)`. Доступ проверяется
**на каждом запросе заново** (`sessionLogin`), так что отзыв доступа действует сразу.

OBS-док авторизуется иначе: постоянный ключ в ссылке, `HMAC(PANEL_SECRET, "obs-dock-v1")[:32]`
— внутри OBS логиниться неудобно. Смена `PANEL_SECRET` отзывает и куки, и ссылки на док.

### HTTP-эндпоинты

Все под секретным префиксом `/<WEB_PREFIX>`:

| Путь | Кто ходит |
|---|---|
| `/health` | мы; жив ли тракт звука |
| `/api/state`, `/api/request` | наши же проверки (заказ руками) |
| `/panel`, `/panel/login`, `/panel/logout` | стример и модеры |
| `/dock?k=…` | встроенный браузер OBS |
| `/api/panel/state`, `/api/panel/<action>` | JS панели и дока; поллинг раз в 2 сек |
| `/twitch/`, `/twitch/login`, `/twitch/callback` | подключение ролей + возврат от Twitch |

Действия панели: `skip`, `pause`, `resume`, `remove`, `up`, `down`, `clear`, `add`,
`volume`, `volume_monitor`, `settings`.

### Звук: `deploy/liquidsoap/radio.liq`

- `request.queue(id="requests")` + `blank()` через `fallback(track_sensitive=false)`.
- `switch` на источник `spotify` (`input.external.rawaudio` из FIFO) — **спит**, флаг
  `spotify_on` всегда `false`, см. PITFALLS.
- **Два выхода `output.harbor` на одном порту 8000**: эфир (`STREAM_MOUNT`) и мониторинг
  для наушников стримера (`MONITOR_MOUNT`), каждый со своим `amplify`. Причина: в OBS один
  фейдер управляет и эфиром, и мониторингом, «тише у себя, так же у зрителей» одним
  источником не сделать.
- `burst=8192` вместо дефолтных 65534 байт — иначе клиент сразу получает 2.7 секунды
  музыки, и они превращаются в постоянную задержку.
- `settings.encoder.metadata.export` перечисляет наши кастомные поля (`source`,
  `requested_by`, `web_url`), иначе liquidsoap их молча срежет.

### `tools/`

`coverage_check.py` — разовый замер «сколько треков со Spotify находится на YouTube/SoundCloud»
(59 треков, 98% покрытие). Не часть рантайма, оставлен как доказательство и как заготовка
для повторного замера.

## 5. Конфигурация

Три уровня, у каждого своя роль:

| Где | Что | Когда меняется |
|---|---|---|
| `.env` (600, на VPS) | секреты и адреса: `TWITCH_*`, `SPOTIFY_*`, `PANEL_SECRET`, `PANEL_ALLOW`, `STREAM_*`, `WEB_PREFIX` | руками при деплое, с перезапуском |
| `settings.json` | `max_duration`, `reward_cost`, `reward_enabled` | из панели, на лету |
| дефолты в коде | `BROADCASTER_LOGIN=f1pah`, `BOT_LOGIN=devnulll_music`, `REWARD_TITLE`, тайминги | при правке кода |

`.env` читают и сервис, и docker compose — один источник правды. Образец с пустыми
значениями: `deploy/.env.example`.

Состояние на диске: `secrets/tokens.json` (600, токены обеих ролей),
`secrets/youtube-cookies.txt` (600), `settings.json`, `cache/`.

## 6. Чего в коде намеренно нет

- **WebSocket для панели.** nginx под него настроен, но панель просто поллит
  `/api/panel/state` раз в 2 секунды — для одной страницы этого достаточно.
- **База данных.** Всё состояние — три файла и память процесса. Перезапуск теряет очередь;
  это приемлемо, очередь живёт минуты.
- **Мульти-тенант.** Канал, награда и токены в единственном экземпляре; на несколько
  каналов пришлось бы переделывать `TokenStore`, `Chat` и EventSub.
- **Нормализация громкости и кроссфейд** (фаза Ф4): на YouTube разброс уровней >10 дБ,
  у части треков пик доходит до −0.2 дБ.
